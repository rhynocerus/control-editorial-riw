# Contribuir

Un objetivo concreto por rama. Explica el problema, implementa el cambio, ejecuta `npm test` y `npm run build`, y presenta una PR con evidencia. No mezcles funcionalidades futuras con correcciones de v0.1.

No subas copias editoriales personales, credenciales, datos de cuentas, archivos `.env` ni contenido ajeno sin permiso. Para probar, utiliza datos sintéticos. No inventes estados, fechas ni pruebas de publicación. Mantén los identificadores y la compatibilidad de los respaldos. Toda migración de formato debe incluir una prueba real de restauración.
